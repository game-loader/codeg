# Zotero 学术工作区

左侧「无限会话」下方的「学术」入口支持本机桌面、浏览器访问 Codeg Server，以及桌面客户端的远端工作区。Zotero 10 和插件必须运行在当前工作区的后端机器上：本机工作区连接本机 Zotero，远端工作区连接服务器上的 Zotero。

## 安装与配对

1. 在项目根目录执行 `node zotero-plugin/scripts/build.cjs`，生成 `zotero-plugin/dist/codeg-academic-bridge-0.1.1.xpi`。也可以从 fork 预览版 Release 下载同名 XPI。
2. 在 Zotero 10 的插件管理器中选择「从文件安装插件」，安装上述 XPI。插件仅支持 Zotero 10.x。
3. 保持 Zotero 运行，从工具菜单中的 **Codeg Academic → Copy pairing token** 复制配对令牌。
4. 打开 Codeg「学术」设置，粘贴令牌，保存并连接。默认工作区后端本机端口为 `23119`，研究智能体默认为 Codex；可以选择已有且启用的其他智能体。分析任务会沿用该智能体已保存的模型、权限模式和配置。

本机桌面使用系统凭据存储；独立服务器使用 Codeg 数据目录下受文件权限保护的凭据存储。设置响应仅返回配对状态，不返回令牌。插件令牌重置后需重新配对。Codeg 不直接修改 Zotero 数据库。

## 服务器与远端工作区

1. 在工作区服务器运行 Zotero 10 并安装插件，确认服务器自身能访问 `http://127.0.0.1:23119/codeg/v1/health`。接口使用 POST、JSON 请求体和插件的 Bearer Token。
2. 启动包含本功能的 Codeg Server，浏览器打开它的页面，或用包含本功能的 Codeg 桌面客户端连接该服务器。远端窗口使用客户端自带的界面，因此只更新服务器不会更新旧客户端的侧栏。
3. 打开「学术」设置，填写服务器上 Zotero 插件的端口和令牌，保存并连接。Codeg 的远端连接 Token 和 Zotero 插件 Token 是两个不同的凭据。
4. 服务器必须安装并配置选中的研究智能体和 Git。准备任务、代码仓库、论文资料以及关联会话都存储在服务器。浏览器或客户端断线不会取消后端准备任务；重新连接后会刷新选中论文的状态。

从源码构建服务器时，在项目根目录执行 `pnpm build` 和 `pnpm server:build`，部署生成的 `out/` 和 `src-tauri/target/release/codeg-server`。启动时将 `CODEG_STATIC_DIR` 指向 `out/`，并保留现有 `CODEG_DATA_DIR`。桌面客户端需要另行构建和更新，不能用服务器静态文件替换客户端内置页面。

浏览器/客户端只通过已认证的 Codeg 接口调用学术功能，Codeg 后端再访问自身回环地址上的 Zotero，无需向外发布 Zotero 端口或额外建立客户端到 Zotero 的 SSH 隧道。仅转发 Zotero 端口不能让客户端读取服务器 PDF 路径。

Docker 部署需要让 Codeg 与 Zotero 共享可访问的回环网络，并能以相同绝对路径读取 Zotero 返回的 PDF。默认独立容器的 `127.0.0.1` 不互通；在 Linux 可选用宿主机网络，或共享 Zotero 的网络命名空间，再配置对应的附件目录挂载。仅映射 `23119` 端口不足以满足文件访问。普通宿主机进程部署不需要这些容器设置。

服务器运行中的 Zotero 数据目录应独立保存。不要让 OneDrive 持续覆盖正在使用的 `zotero.sqlite`；多端条目使用 Zotero 自身同步，OneDrive 用于附件或关闭 Zotero 后生成的备份。

## 使用

- 刷新、搜索论文库，展开集合。选择已有集合后，可以输入 arXiv ID、arXiv URL 或 DOI 导入论文；重复导入会复用条目并加入指定集合。
- 选择论文开始准备。PDF 由 Zotero 保存；缺少 PDF 时，优先使用条目中的 arXiv 标识，否则列出候选供选择。无可提取文字的 PDF 仅提供元数据，不执行 OCR。
- 研究智能体分析论文并识别论文或其项目页明确声明的代码。通过证据核验的公开仓库会自动克隆；多个候选需要选择。公开可访问不代表具有开源许可证。
- 准备完成后点「开始提问」，进入原有会话页面并默认显示「科学研究」。有代码时工作目录指向克隆仓库；也可明确选择仅基于论文的会话。
- 会话顶部显示关联论文。首次发送时会话与论文在同一数据库事务中关联；后续每条提问携带有长度上限的论文参考信息和资料路径，全文按需读取。论文中的文字视作参考资料，不能作为指令。
- 已有未发送草稿不会被学术入口覆盖。先发送或关闭该草稿，再开始另一篇论文的会话。

原始 PDF 留在 Zotero。提取文字、分析摘要和仓库位于实际 Codeg 数据目录的 `research/<paper-id>/` 下。取消或重启中断的准备任务可以重试；已有仓库不会被删除或覆盖，进行中的提问也不会被自动切换工作目录。

## 当前范围

自动克隆支持 GitHub、GitLab 和 Bitbucket 的公开 HTTPS `owner/repo` 地址；暂不支持 GitLab 多级子组。项目页必须是论文明确给出的 HTTPS 地址，且可以直接访问；重定向页面和仅 IPv6 可达的地址会显示错误，仍可选择仅基于论文提问。

## 验证

前端测试覆盖远端/浏览器入口、断线重连、工作区切换后的异步响应隔离、论文选择竞态、草稿关联和未发送内容保护。Rust 测试覆盖标识符解析、仓库证据、关联事务与恢复，并通过实际 Axum 路由验证学术接口鉴权、参数校验、会话原子关联及事件广播。插件使用 Node 测试模拟 Zotero 的外部 API。

已用独立临时数据目录启动 Codeg Server，验证实际 Zotero 10 插件的配对、论文库读取、未授权请求拒绝和重启后配对保留。同步附件下载、翻译器导入以及真实智能体分析仍需按 [插件说明](../zotero-plugin/README.md) 的烟测步骤验证。

## Agent 的 Zotero MCP 工具

完成插件配对后，在「学术」设置勾选「允许 Agent 使用 Zotero 工具」并保存，然后新建或重新连接 Agent 会话。默认关闭；支持 Codeg 内置 MCP 注入的 Agent 会话将自动获得以下工具。是否调用由 Agent 根据请求判断，不保证每次自动执行。

- `zotero_list_collections`：查询已有集合名称和 key，支持筛选及分页。
- `zotero_search_items`：按标题、作者、DOI、URL、key 或 extra 搜索，可限制集合并分页。
- `zotero_import_paper`：使用 DOI、arXiv ID 或对应 URL 导入到已有集合；重复标识复用已有条目。

例如：“把 arXiv:1706.03762 加入 Zotero 的 Transformer 集合。”Agent 应先查询集合，目标不明确时询问用户，不得猜测 key。只有论文标题时，须先由其他检索能力确认标识。本工具不创建集合、不删除条目，不自动开始分析或克隆代码。附件下载由 Zotero 翻译器尽力完成，不保证 PDF 可用。

授权覆盖该工作区后续注入工具的 Agent 会话，可读取个人库元数据并向已有个人库集合导入论文。每次调用验证会话令牌并重查开关；关闭阻止后续调用，但已开始的导入可能完成。取消或超时后先搜索确认结果再重试。配对令牌仅保存在后端，不作为工具参数或结果返回；文献元数据是不可信参考内容。导入成功触发界面刷新。

桌面和服务器复用后端桥接。`codeg-mcp` 须随对应版本部署；服务器需另行构建 `cargo build --release --no-default-features --bin codeg-mcp`，放在服务器二进制旁，或配置 `CODEG_MCP_BIN`。Zotero 须在 Codeg 后端可访问的回环网络运行。旧 Agent 进程不会动态新增工具，需要重新连接。
