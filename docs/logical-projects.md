# 单窗口项目、机器与会话历史

Mac 桌面端的主工作区可以同时连接本机和多台 Codeg Server。保存远端连接后，在主窗口侧栏访问它们；无需为每台机器另开远端工作区窗口。原来的独立远端窗口入口仍可使用。

## 同源仓库如何显示

侧栏默认使用「项目」视图。同源仓库在不同机器、目录和工作树上的会话直接汇总到一个项目历史中；每行保留机器与工作树标记。切换「机器」视图可以按执行位置浏览。

```text
someone/foo
├─ 修复登录问题       机器 A · feature/login
├─ 更新 API          机器 B · feature/api
├─ 仓库分析           机器 A · 仓库目录
└─ 修复测试           机器 B · 仓库目录
```

识别依据是 Git fetch remote，优先选择可用的 `upstream`，其次是 `origin`，再选择其他可用的 remote。GitHub 的 SSH 和 HTTPS 地址、大小写和 `.git` 后缀会统一成相同来源；本地目录路径不参与同源判断。配置了相同 upstream 的两个 fork 也会归到同一个项目。

没有可识别远程地址的仓库、本地普通文件夹，以及无法确定真实主机的 SSH 别名，会保持独立。企业 GitHub 和其他 Git 服务的主机边界仍保留；其他 Git 服务的仓库路径大小写不会被随意合并。

## 添加项目

侧栏顶部的「+」（添加项目）在「项目」和「机器」视图中都可用。对话框顶部的「机器」下拉先选项目所在的机器：默认是当前聚焦且已连接的机器，否则是本机。目录浏览、新建文件夹和打开都在所选机器上执行；还在打开时不能切换机器。打开后项目归属这台机器，按来源与其他机器上的同源仓库汇总。「机器」视图中每台机器行上的「+」仍直接在该机器上打开，同样可以在对话框里改选。

## 查看原来的会话

展开项目即可浏览各机器和工作树的历史，无需逐台机器展开。选择已有会话会打开原会话；已完成和置顶会话保持可访问；最近会话摘要可以继续显示更多。机器、工作树和路径标记帮助区分来源。

桌面主工作区使用统一左侧栏，新建会话、搜索、导航和会话管理都从这里进入，主区域不再嵌入一套旧侧栏。「新建会话」会明确选择运行机器和目录；选择目录或打开已有历史不会自动创建草稿。普通聊天也保持可访问。

「无文件夹聊天」按机器显示为可折叠的小文件夹，机器名放在分组标题中，组内只显示对话标题，避免每行重复机器名称。「最近会话」仍显示来源，便于辨认来自不同机器的聊天。

```text
无文件夹聊天
├─ 机器 A
│  ├─ 对话标题一
│  └─ 对话标题二
└─ 机器 B
   └─ 对话标题三
```

项目有多个运行位置时，先选机器和目录，再新建会话或打开文件、Git、终端与工作树管理。文件/Git 可以与保留的普通聊天草稿一起查看；返回聊天时恢复聊天详情。委派子会话显示并使用自己所属的目录。

同一窗口内可保留多个会话标签。需要同时查看不同工作树的会话时，使用会话标签右键菜单的拆分或拆分并移动操作；跨机器查看使用主工作区的机器分屏。

## 更新与恢复

此功能需要支持项目身份接口的新 Codeg Server。旧服务器仍能显示各自的目录和会话，并在对应机器提示升级。升级后手动刷新可以重新尝试识别，无需删除连接。

改变 Git remote 后刷新，会重新计算项目分组。临时断线会保留当前连接中已成功取得的信息；更换服务器地址、令牌或删除连接会废弃旧连接的信息，避免把旧服务器的目录和会话编号用于新服务器。

同源聚合只影响浏览和分组。文件、分支、Git 操作、会话、任务和终端始终运行在具体机器及目录上，不会自动同步文件、合并会话数据、重新克隆或搬迁仓库。

## iOS

iOS 的项目目录也提供「项目 / 服务器」视图。展开同源项目可以直接查看跨服务器、仓库目录和工作树的会话历史，每行显示原服务器与目录来源。新任务和文件夹操作明确选择执行位置，文件、Git 和终端入口保持可访问。

iPad 可以使用既有服务器分屏；切换目录视图只改变展示，不会重建各服务器的会话草稿或已保留的项目运行状态。
