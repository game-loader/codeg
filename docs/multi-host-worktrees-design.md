# 单窗口多机器仓库与 worktree

日期：2026-10-10

状态：方向已由用户确认（2026-10-16），按「过渡阶段」分步实现中。

## 目标与首版连接方式

用户当前需要为两台机器分别打开远程工作区窗口，希望像 Orca 一样，在一个 Codeg 窗口中管理不同机器上的仓库和 worktree。

首版建议复用已经配置的 Codeg Server 连接。桌面端的一个窗口同时连接本机和多台 Codeg Server；新增连接、浏览远端目录、打开仓库、创建和删除 worktree、查看与编辑文件、运行 Git、终端和智能体会话，均在该窗口完成。

直接 SSH 连接属于另一种连接器：包含主机认证、远端运行环境准备、进程管理和隧道。这里的机器身份与工作区模型允许随后增加该连接器；本草案的首版验收以现有 Codeg Server 为前提。连接方式问题已向用户提出，用户选择 SSH 时需同步调整范围和部署设计。

## 用户交互与验收场景

侧栏采用项目优先（用户于 2026-10-16 确认，替代原先的「机器 → 仓库 → worktree」树）。顶层是逻辑项目，下面是它在各机器上的落点和 worktree。只有一台机器时不显示任何机器信息；同一项目横跨多台机器时，行上显示机器标签。Hosts 筛选显式选中两台及以上、且至少两台有内容时，才按机器插入分组标题。

新增项目对话框顶部有机器下拉。默认值依次为：触发上下文的机器（例如从某机器节点发起）、当前聚焦的机器、本机；直接访问单个 Codeg Server 的 Web 页面没有本机，只有该服务器。下拉中未连接的远端提供「连接」，并可当场新增连接。目录浏览、新建目录、克隆和项目启动器都经所选机器的客户端执行。

新建会话或 worktree 时提供「运行于」。列出该项目已就绪的机器，以及已连接但尚无落点的机器（提供「设置项目位置」：浏览已有目录或克隆）。未手动选择时，优先当前聚焦机器上的落点，否则取第一个就绪落点；显式指定的机器没有落点时报不可用，不改用其它机器。

1. 已有机器 A、B 的连接时，启动 Codeg 后在同一侧栏看到两台机器上的项目；A、B 上 origin 相同的仓库显示为一个项目。
2. 在 A 的仓库创建 `feature/a` worktree，在 B 的仓库创建 `feature/b` worktree；两个操作均在选择的机器上执行。
3. 同一窗口同时保留 A、B 的会话与文件标签。点击标签后，文件、Git、终端、任务和智能体操作使用该标签绑定的机器。
4. 使用现有左右或上下分屏，同时显示不同机器的会话；每个分组拥有明确的机器和 worktree 上下文。
5. 在 A 运行任务后切到 B，A 的后端工作继续，进度仍能更新到 A 的标签和侧栏。切换不会被视作关闭会话或取消任务。
6. A 断线、认证失效或重新连接时，B 仍能操作；错误只显示在 A 的节点与工作区中。
7. 重启后恢复每台机器的打开仓库、worktree 与标签位置；离线机器保留可辨认的占位标签，重连后恢复。

## 当前代码约束

- `src/lib/transport/index.ts` 只有一个 `_remoteTransport`；`getTransport()` 隐式选择整个窗口的后端。
- `src/contexts/remote-connection-context.tsx` 从 URL 初始化远端，并明确依赖「一个 JS realm 的后端身份终身不变」。
- `src/stores/backend-scoped-store-reset.ts` 只重置单例状态，不失效在途请求，也没有完成切换渲染、ACP 引用计数和订阅的隔离。
- workspace、tab、conversation runtime、academic 等 store 存在模块单例；不同服务器的数字 ID 可以相同。
- `src-tauri/src/commands/remote_proxy.rs` 已以 `connection_id` 管理 HTTP 与 WebSocket 路由，可作为多机器连接的基础。
- 已有 Git worktree 创建、删除、分支解析和文件夹注册能力，集中在 `src/lib/api.ts`、`src-tauri/src/commands/folders.rs` 与 `src-tauri/src/web/handlers/git.rs`。
- 浏览器表面运行在本机 shell；远端流量出口、HTML 文档读取、文件传输和 Git 操作弹窗需要单独保持机器归属。

## 方案比较

### 推荐：Codeg Server 多后端工作区

一个窗口管理多个后端 runtime。每个 runtime 拥有固定 transport、API 客户端、store 和事件订阅；窗口负责统一侧栏、标签和分屏。复用现有 Rust 代理及 Codeg Server 的业务接口。

优点是直接解决多窗口问题，也能覆盖真实开发操作；代价是需要将前端对单一后端的隐式依赖显式化。

### 直接 SSH 与自动准备远端服务

在上述机器模型上增加 SSH 连接器，为每台机器准备运行环境，再通过隧道连接受控的 Codeg 后端。交互接近 Orca 的 SSH worktree。

它还能降低用户部署服务器的负担，但需要另行定义密钥、跳板机、远端安装与升级、隧道重连、平台兼容和进程归属，实施范围更大。

### 每机器嵌入独立页面

在一个外层窗口中嵌入多个独立页面，以保留当前每页面单例的隔离。

它减少 store 改造，但会引入多套界面、快捷键与窗口生命周期，并使原生浏览器表面、弹窗和统一分屏难以协同。首版采用显式多后端 runtime。

## 机器和资源身份

定义 `BackendKey = "local" | "remote:<connectionId>"`，由本机保存的远端连接 ID 决定。机器名称用于显示；路径和数据库数字 ID 不承担机器身份。

前端跨机器资源以 `{ backendKey, id }` 或 `{ backendKey, path }` 引用。仓库、worktree、会话、任务、文件、终端、标签、通知和恢复记录都必须包含 `backendKey`。

既有后端数据库与业务 ID 保持各机器自己的格式。请求抵达相应 transport 时仅发送该后端的原始 ID；跨机器组合身份仅用于窗口级前端索引和路由。

`backendKey` 与运行代次分别处理：连接地址或凭据变更时更换 runtime generation，废弃旧订阅和在途写回。连接地址变化时失效该机器缓存，重新读取仓库与会话，不能把旧服务器的 ID 直接用到新服务器。

## 连接与 API 路由

新增窗口级 `BackendRegistry`，维护每个后端的描述、连接状态、generation 与固定 transport。保持 `getShellTransport()` 专用于本机窗口、连接配置、系统能力和原生浏览器等操作。

新增 `BackendClient`，以固定 transport 调用现有业务接口。React 工作区通过 `BackendWorkspaceProvider` 取得当前客户端；store、事件处理和非 React 回调显式接收所属客户端。

任何异步操作在发起时固定客户端、资源身份和 generation。重试、上传后继续提交、文件保存、终端输入、权限回复和结果写回均使用原绑定，不能在 `await` 后重新读取当前选中的机器。

目标解析失败或机器离线时返回该目标的不可用状态，不静默改成本机或另一台机器。各主机目录并行加载并独立合并，保留离线机器的已有目录快照；后台完成消息可以更新原机器的摘要，但不能抢占用户正在查看的标签。

原有单后端 Web 页面及独立操作窗口继续使用默认客户端兼容入口。多机器工作区中的业务调用迁移到显式客户端，兼容入口不承担多机器路由。

迁移方式：`src/lib/api.ts` 的业务函数逐个增加可选的末位 `target` 参数，省略时使用窗口 transport，行为不变。调用方的目标从资源自身的机器标记推出（例如对话框打开时固定的根文件夹所属机器），不读「当前机器」。

Rust 代理保持以 `connection_id` 分流。为连接配置变更增加绑定版本校验，避免旧工作区在连接地址被编辑后将旧资源 ID 发送到新后端；校验失败要求重建该机器的 runtime 并刷新数据。

绑定校验分两步落地。第一步在前端：远端客户端在创建时记下连接的服务地址，每次写操作前重新读取连接配置，地址变化或连接已删除时拒绝并提示重新选择机器。这一步有极短的检查与发送间隙。第二步在 Rust 代理：`remote_http_call` 接受期望的绑定并在代理内比较，消除该间隙；它属于 `tauri-runtime` 代码，需要 CI 的桌面构建验证。

更新或删除连接时，HTTP、事件 WS 和浏览器出口共同失效；WS 重连重新读取连接配置。区分网络不可达与服务器明确的认证拒绝，不能把连续网络失败当作令牌失效。统一窗口以独立 instance ID 登记所连接的机器，并在销毁时释放全部对应订阅。

## Store、订阅和生命周期

将后端资源 store 改为可实例化工厂。每个 `BackendRuntime` 至少拥有 workspace、conversation runtime、ACP agent/connection、academic 和任务数据；工厂内部的缓存、请求去重、墓碑、计时器与模块监听也随实例隔离。

窗口级标签以机器和资源组合键去重。会话与文件面板消费该标签的 runtime；允许两个分屏的活动机器不同，不能以全窗口当前机器决定分屏内的操作目标。

每个 runtime 使用独立订阅。侧栏聚合各 runtime 的摘要，详细会话使用现有 snapshot/replay attach 协议恢复。后台 runtime 保留必要订阅与任务状态；可停止隐藏视图的绘制与轮询，不能因切换显示机器而销毁活跃会话。

移除机器或关闭窗口时才释放相应订阅与客户端。停止观看、断开客户端和取消后端任务是不同操作；取消由现有明确的任务或会话操作触发。

## 项目身份

各 Codeg Server 拥有独立数据库，后端不新增跨机器的项目表，也不给文件夹增加机器字段；机器归属由所属 runtime 的 `backendKey` 决定。项目身份由窗口级前端从各后端的 `git_list_remotes` 结果推导：

- 优先 `origin`，没有时取按名称排序的第一个 remote。
- URL 规范化为 `git:<host>/<path>`：支持 https、ssh://、scp 风格（`git@host:owner/repo`）与 git://，去掉凭据、端口、末尾 `/` 和 `.git`，host 小写；github.com 与 gitlab.com 等常见托管的路径也小写。
- 无 remote 的 Git 仓库或普通文件夹使用 `local:<backendKey>:<folderId>`，只属于一台机器，永不合并。
- worktree 文件夹沿用其 `parent_id` 根文件夹的身份。

用户可以随后显式「拆分/合并」项目，覆盖记录保存在窗口级布局中；不按同名路径或目录名自动合并。

## 仓库与 worktree 操作

仓库列表使用每个后端的文件夹列表及父子关系，再按项目身份聚合。新增仓库时，目录浏览、路径校验和打开目录均通过所选机器的客户端完成。

提供完整 `git_list_worktrees` 数据，包括规范化路径、分支、HEAD、主工作树、detached、locked 与 prunable 状态。Rust 核心负责解析 Git 的结构化输出，Tauri 和 Web handler 复用同一函数。

创建 worktree 的表单固定机器和仓库，支持新分支名称、基础引用及远端目标路径。后端现有 `git_worktree_add` 已支持可选 `base`，在固定客户端中暴露该参数，省略时沿用 HEAD 的行为。Git 创建成功后注册 worktree 文件夹并读取权威结果，随后打开该机器下的新会话；注册失败保留实际 Git worktree，并提供重新注册操作，不能重复创建或报为完整成功。

移除操作固定资源身份，沿用现有脏文件、未合并分支及强制删除确认。拒绝主工作树、操作所处的当前工作树，以及仍被运行中或合并中的待办任务占用的目录。增加按规范化路径定位的移除核心入口，使 detached worktree 也能移除；旧按分支入口复用相同保护逻辑。bare 条目显示为仓库信息，不提供 worktree 移除操作。完成后只清理该机器的目录节点与相关标签，不能误删另一台机器上同名分支的 worktree。

## 文件、终端、浏览器和弹窗

文件标签与编辑草稿包含机器身份，两个机器上的同一路径是两个文件。保存、下载、上传和外部修改检测固定所属客户端。

终端标签记录机器、目录和后端终端 ID；输入、resize、输出与退出事件在同一 runtime 内匹配。切换标签不会执行终端关闭逻辑。

浏览器原生能力仍调用本机 shell，但每个浏览器标签记录所属机器，指定对应的远端流量出口和目录上下文。同一窗口的两个 `localhost:3000` 可以分别访问两台机器上的服务。

远端浏览器出口沿用现有平台能力检测；不支持的表面显示具体不可用状态。Web 浏览器桥接与原生 TCP 出口保持各自能力范围，不能把仅支持 loopback HTTP 的桥接描述为完整的远端浏览器能力。

Git 提交、合并等独立弹窗携带显式 `remoteConnectionId` 和机器内资源 ID，避免从全窗口的活动连接推导目标。机器名称同时显示在操作上下文中。

文件传输进度绑定机器和发起者身份，定向投递到发起窗口；取消时校验发起者和机器归属。移除连接时取消该连接正在进行的传输并报告取消结果，不影响其他连接；仅断网时按该传输的失败结果处理，重新连接不自动重复上传或下载。

## 持久化与兼容

连接配置继续存储于本机的 remote connection 服务。新增窗口级布局记录版本，保存机器组合资源键、跨机器标签顺序、分屏和选择状态；访问令牌不写入标签、布局或日志。

各服务器的 `opened_tabs` 仍只保存自己的会话和文件夹 ID。窗口统一标签持久化按机器拆分提交，不能向 A 保存 B 的会话 ID。

旧本机窗口和 `?remoteConnectionId=...` 远端窗口在恢复时生成单机器上下文。旧布局缺少机器字段时，仅在明确的旧窗口后端下迁移，不能猜测同名路径属于哪台机器。

桌面端提供首版多机器入口；直接访问一个 Codeg Server 的浏览器和现有移动端保留单后端流程。Next.js 保持静态导出，路由上下文使用查询参数或窗口内状态。

新增文案仅适配简体中文和英文。

## 错误与恢复

- 离线或超时：只更新对应机器状态；在途写操作不自动重复，重连后读取权威状态。
- 认证失效：对应机器的操作暂停，修复其连接后重建该 runtime；其他机器继续运行。
- 已删除目录或会话：保留明确的资源不可用状态，并提供关闭标签或重新定位目录操作。
- 连接配置变化：旧 generation 回调丢弃，重新建立 HTTP/WS 绑定并读取快照。
- 旧版本后端缺少完整 worktree 接口：显示明确的升级要求，已有目录、会话和文件仍按兼容能力使用。

## 验证标准

单元与组件测试使用两套后端替身，故意让两台机器具有相同 folder、conversation、task 和 terminal ID，以及相同文件路径与分支名。

必须覆盖：跨机器创建/移除 worktree 路由；A 的延迟请求在用户切到 B 后返回；两个分屏并行发送和审批；后台任务不中断；A 断线或 401 不影响 B；连接地址变更后旧请求和事件被拒绝；文件保存与传输进度归属；远端 localhost 浏览器出口；标签、分屏和旧布局恢复；部分创建成功后的注册恢复。

Rust 测试覆盖 worktree 结构化解析和命令参数，以及共享核心的 HTTP 路由、代理配置版本和订阅释放。命令执行验证使用临时 Git 仓库，不操作用户真实远端仓库。

完成后执行前端 lint、Vitest、TypeScript 检查与静态构建，以及受影响 Rust 桌面/服务器模式的 check、test 和 clippy。真实桌面烟测需要两台已授权的 Codeg Server 或两套临时服务器，验证上述 A/B 场景；环境无法提供时明确报告尚未验证的桌面与远端行为。

## 推荐实施顺序

1. 机器和资源身份、连接注册表、固定客户端及后端路由约束。
2. 逐个实例化后端 store、事件和异步回调，形成可隔离的 runtime。
3. 项目身份推导、项目优先侧栏、带机器选择的新增项目与「运行于」，以及完整 worktree 操作。
4. 跨机器标签和分屏，以及文件、终端、浏览器、操作弹窗和恢复。
5. 执行冲突身份、断线恢复、跨模式回归及双服务器烟测。

每一步都围绕同一验收目标推进，完成到第 4 步后才形成完整的单窗口多机器开发体验。

过渡阶段（用户于 2026-10-16 选择先行）：在第 1、2 步完成前，本地桌面窗口的侧栏先只读聚合各机器的项目。本机文件夹若在其它机器上也有落点，标题上显示「也在 …」标记，右键「在其它机器上打开」；只在其它机器上的项目单独列在「文件夹」区内，点击打开或聚焦该机器的现有远端窗口。会话、文件、终端仍在各机器自己的窗口中操作。实现见 `src/lib/project-identity.ts`、`src/lib/backend-client.ts`、`src/lib/project-catalog.ts` 与 `src/hooks/use-project-catalog.ts`。

同一阶段，「打开文件夹」对话框在本地桌面窗口中有机器下拉（至少保存了一个远端连接时出现，默认本机）。选中远端时，浏览、新建目录、打开文件夹和关联目录都经 `pinBackendClient` 发到那台机器；打开的文件夹不写入本窗口的 store，由侧栏汇总显示，完成时可直接打开那台机器的窗口。克隆仓库和项目启动器尚未接入机器选择。

## Orca 对照与适配边界

调查依据是 Orca `180e8c186f779bc8bfbddc93391855e03eeee006`（2026-10-10），多机器请求与状态部分于 `33e6785f`（2026-10-17）复核。采用其分层身份、显式执行目标、各主机独立目录加载、generation 过滤和独立订阅生命周期；使用 Codeg 的 Rust 代理、现有 Folder 父子关系与 ACP 会话能力实现这些机制。

| 方面 | Orca | Codeg 的做法 |
| --- | --- | --- |
| 运行边界 | 每台远端机器运行 Orca 服务，SSH 主机也连到受管服务；客户端只是界面 | 相同：每台机器运行 codeg-server |
| 请求目标 | 每次调用经 `callRuntimeRpc(target, …)` 显式指定 `local` 或某个环境；目标从资源自身的归属推出，从不读当前聚焦的服务器，归属不一致时拒绝 | 相同原则：`BackendClient` 显式指定机器，`api.ts` 函数逐步增加可选 `target` |
| 状态 | 渲染层只有一个 store，行带主机字段；新代码使用「主机 + id」组合键，旧的裸 id 映射保留，并以碰撞索引兜底，破坏性操作必须显式指定主机 | 不照搬单 store：Codeg 的 ID 是各数据库自增整数，跨机器必然重复，无法新旧键并存渐进迁移。后端数据每台机器一份 store，窗口层（标签、侧栏、分屏、恢复）使用带机器的组合键 |
| 防串机器 | 请求发出时记下环境配对版本，主进程在版本变化时拒绝；写操作另核对连接代次 | 前端先校验连接地址未变，Rust 代理随后补上代理内校验（见「连接与 API 路由」） |
| 事件 | 主进程按订阅 id 管理，订阅归属发起窗口；窗口销毁、配对版本或传输代次变化时失效 | Rust 代理已按 `connection_id` 分开 WS 任务和事件通道，只投递给已订阅的窗口；单窗口同时订阅多个连接尚未验证 |
| 目录加载 | 本机与所有远端并行加载，单台失败不影响其它，代次号丢弃过期结果 | 相同；另外连接地址变化时丢弃该机器的旧快照 |

对应文件：`src/renderer/src/runtime/runtime-rpc-client.ts`、`src/renderer/src/lib/resolve-owner.ts`、`src/renderer/src/lib/file-owner-runtime-target.ts`、`src/shared/worktree/host-qualified-identity.ts`、`src/renderer/src/runtime/runtime-environment-revision.ts`、`src/renderer/src/store/host-catalog-fencing.ts`。

- `src/shared/execution-host.ts`：执行主机身份。
- `src/shared/project-types.ts`：逻辑项目在各主机上的仓库落点。
- `src/shared/worktree/identity.ts`：主机限定的 worktree 身份。
- `src/renderer/src/store/repos/all-host-repo-catalog-actions.ts`：多主机目录加载与增量合并。
- `src/main/ipc/runtime-environment-subscription-handlers.ts`：订阅归属和生命周期。

Codeg 与 Orca 一样以项目组织侧栏并提供机器筛选，项目身份同样来自 git remote；不能靠同名路径自动认定为同一项目。Electron IPC/preload 和 Node relay 不是 Codeg 的运行边界，不整块复制为依赖。
